# Foundation 2주차 · AI와 함께 일하기 #2

상태: 헤드메시지 수정안. HTML 제작 전 검토본.

## 핵심 메시지

큰 단위의 일을, AI가 실행하고 확인하고 수정하며 반복할 수 있는 업무 루프로 만든다.

PRD는 무엇을 완성할지, operational rules는 어떤 기준으로 일할지, loop는 결과를 보고 어떻게 다음 행동을 이어갈지 정의한다. 모든 업무에 긴 문서를 요구하지 않는다. 업무 규모와 실패 비용에 맞는 최소한의 기준을 AI와 함께 작성한다.

## 16장 헤드메시지

| 장 | 헤드메시지 | 본문에서 보여줄 내용 |
|---|---|---|
| 1 | AI와 함께 일하기 #2 — 큰 일을 끝내는 루프 만들기 | 목표는 AI에게 실행·검증·수정의 반복까지 맡길 수 있는 업무 구조를 설계하는 것. |
| 2 | 매번 다음 행동을 사람이 지시하면, 큰 일은 계속 내 손을 기다립니다. | ‘만들어 줘 → 확인해 줘 → 고쳐 줘’를 사람이 매번 이어주는 흐름. 다음 행동을 정하는 기준까지 전달할 필요를 제시한다. |
| 3 | 반복을 맡기려면, 목표·운영 규칙·피드백이 연결되어야 합니다. | PRD: 무엇을 완성할까? 운영 규칙: 어떤 기준으로 일할까? 피드백 루프: 결과를 보고 다음에 무엇을 할까? 전체 구조를 제시한다. |
| 4 | PRD는 AI가 완성해야 할 업무와 그 범위를 고정합니다. | 관통 예시 ‘참가 신청부터 운영진 조회까지’. 사용자·목적·필수 결과·제외 범위를 한 장에 정리한다. 구현 방법을 전부 미리 지정할 필요는 없다. |
| 5 | 완료 기준은 실제 결과를 보고 판정할 수 있어야 합니다. | ‘신청 관리가 잘 된다’를 ‘참가자가 가능한 일정을 제출하면 운영진이 동일한 정보를 조회할 수 있다’로 구체화한다. |
| 6 | 운영 규칙은 일하는 도중의 선택을 일정한 기준으로 묶습니다. | 기존 시스템을 유지할 범위, 작업과 확인의 순서, 변경하지 말아야 할 조건을 정한다. PRD의 목적지를 향해 어떻게 진행할지 설명한다. |
| 7 | 스스로 처리할 일과 사람에게 물을 일을 구분합니다. | 합의된 범위의 구현·오류 수정은 진행. 개인정보 수집 항목이나 업무 범위 변경은 질문. 각각의 상황에 연결된 판단 기준을 보여준다. |
| 8 | 실행 결과가 다음 행동의 입력이 되면, 작업이 루프로 이어집니다. | 실행 → 관찰 → 완료 기준과 비교 → 다음 행동 결정 → 실행. PRD와 운영 규칙이 루프의 어느 판단에 쓰이는지 연결한다. |
| 9 | 루프에는 결과를 실제로 확인할 수 있는 수단이 필요합니다. | 테스트, 화면, 저장된 데이터 등으로 결과를 관찰한다. 이번 예시에서는 신청 제출과 운영진 조회로 확인한다. 에이전트의 완료 보고만으로 통과시키지 않는다. |
| 10 | 실패한 검증 결과를 다음 수정 작업으로 연결합니다. | 신청은 저장됐지만 선택 시간이 조회 화면에 빠진 상황. 기대값과 실제값의 차이를 확인하고 원인을 찾아 수정한 뒤 다시 같은 흐름을 확인한다. |
| 11 | 완료·재시도·사람에게 질문할 조건이 있어야 루프가 끝납니다. | 기준 충족 시 완료, 범위 내 오류는 수정, 반복 실패·필수 접근 부재·중요한 결정 미정이면 중단 후 보고. 작업에 맞춰 시간·비용 한도도 정한다. |
| 12 | 목표와 규칙을 묶으면, 한 번에 맡길 업무의 구조가 만들어집니다. | PRD + 운영 규칙 + 검증 방법 + 종료 조건을 하나의 실행 요청으로 조립한다. AI에게 초안을 만들게 하고 사람이 중요한 선택을 확인한다. |
| 13 | 실제 흐름 ① — 구현부터 동작 확인까지 이어서 맡깁니다. | 교육용 예시: 기존 앱 확인 → 합의된 범위 구현 → 테스트 신청 → 저장·조회 확인. 각 단계의 결과가 다음 단계로 넘어가는 모습을 보여준다. |
| 14 | 실제 흐름 ② — 오류는 수정하고, 새로운 결정은 사람에게 돌려줍니다. | 같은 예시에서 조회 오류는 수정·재검증하고, 추가 개인정보가 필요하다는 제안은 실행하지 않고 사람에게 질문하는 분기를 보여준다. |
| 15 | 사람은 중요한 선택과 최종 결과에 집중할 수 있습니다. | 같은 업무의 전체 타임라인에 사람의 개입을 표시한다: 목표·기준 합의, 필요한 예외 판단, 최종 사용 확인. 맡긴 반복 작업과 남은 판단을 구분한다. |
| 16 | 이제 업무 하나를, 실행·검증·수정까지 맡길 수 있게 설계합니다. | 무엇을 완성할지, 어떤 규칙을 지킬지, 결과를 어떻게 확인할지, 언제 멈추거나 물을지 설명할 수 있는 상태가 이번 주차의 도달점이다. |

## 표현과 예시 원칙

- 관통 예시는 스터디 참가 신청·운영진 관리 업무를 교육용으로 단순화한 것이다. 실제 개발 로그나 시연 성공 기록으로 표현하지 않는다.
- 13~14장은 앞에서 설명한 구조가 실제 작업 순서와 분기로 어떻게 연결되는지 보여주는 적용 장면이다.
- PRD와 규칙은 AI와 함께 만드는 최소한의 작업 기준이다. 사람이 모든 구현 세부사항을 통제해야 한다는 의미로 설명하지 않는다.
- 반복은 실제 도구 접근과 실행 환경 안에서 이루어진다. 결과를 관찰할 수 없는 상태를 성공으로 취급하지 않는다.
- OT·1주차 HTML 디자인을 이어가며, 동일한 업무의 PRD·규칙·루프가 순서대로 조립되도록 시각화한다.
