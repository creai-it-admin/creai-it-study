# CREAI+IT AI 스터디 0기 앱

스터디 운영을 굴리고, 다음 운영을 고칠 데이터를 쌓는다.

대면 세션 두 시간을 이 앱 하나로 진행한다. 커피빈에 스크린이 없어서 장표를 각자 노트북으로
보고, 2부 인클래스 답변을 여기에 쓰고, 운영진이 구간을 넘긴다.

Phase 1을 기반으로 리허설에 필요한 Phase 2 일부(회차 결과, 지난 내 제출물, 주제·폼 편집)를 추가했다. 스터디 도메인 테이블은 여덟 개를 유지한다.

## 세팅

```bash
npm install
cp .env.example .env      # 값을 채운다
npm run db:push           # 스키마를 DB에 민다
npm run db:seed           # 회차 다섯 줄과 1주차 폼을 넣는다
npm run dev
```

### 환경 변수

| 이름 | 무엇 |
| --- | --- |
| `NEXTAUTH_URL` | 로컬은 `http://localhost:3000` |
| `NEXTAUTH_SECRET` | `openssl rand -base64 32`로 만든다 |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | 구글 OAuth. 리디렉션 URI는 `<주소>/api/auth/callback/google` |
| `DATABASE_URL` / `DIRECT_URL` | Supabase Postgres 접속 문자열 |
| `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` | 장표 PDF 업로드용 |
| `SUPABASE_STORAGE_BUCKET` | 공개 버킷 이름. 기본 `decks` |
| `ADMIN_EMAILS` | 쉼표로 구분. 여기 있는 계정은 첫 로그인에 운영진이 된다 |

**퍼블릭 레포다.** `.env`는 커밋하지 않는다. 참가자 이메일은 코드에도 시드에도 환경 변수에도
안 들어간다. 각자 구글로 가입하면 그때 계정이 생긴다.

`ADMIN_EMAILS`에 이메일을 나중에 추가하면 그 사람이 **다시 로그인해야** 운영진이 된다.
역할은 로그인 시점에 DB에 쓰이기 때문이다.

## 어떻게 도나

운영진이 `/admin`에서 회차에 장표를 올리고 세션을 시작하면 그 회차가 `running`이 된다.
날짜를 보지 않는다. `running`인 회차 하나만 본다. 그래서 리허설 회차로 아무 때나 끝까지
돌려 볼 수 있다.

참가자 화면은 3초마다 `/api/state`를 물어 현재 구간을 받는다. **구간이 바뀌는 순간에만 한 번**
그 구간 화면으로 옮기고, 그 뒤 참가자가 스스로 옮긴 경로는 다음 구간이 바뀔 때까지 건드리지
않는다. 2부에 장표를 다시 열어 봐도 끌려가지 않는다.

타이머는 서버 시각 기준이다. 상태 응답의 서버 시각으로 시차를 재 두고 보정해서 센다.
1부에는 안 뜨고 2부, 휴식, 3부에만 뜬다.

인클 폼은 입력 즉시 브라우저에 초안을 남기고, 입력을 멈추고 2초 뒤에 서버에 저장한다.
저장 요청은 하나씩 보내며 10초 안에 응답이 없으면 5초 뒤 재시도한다. 새로고침 후에도
초안과 제출 요청을 복원해 다시 보낸다. 브라우저 저장소를 사용할 수 없으면 화면에 알린다.

저장은 처음 불러온 제출물 ID와 저장 버전을 확인한다. 회차가 닫혔거나 다른 저장과 충돌하면
초안을 보존하고 안내한다. 충돌 안내가 나오면 글을 확인한 뒤 다시 제출한다.
구간 전환도 운영진이 보고 있는 구간을 확인하므로 같은 요청으로 두 구간을 넘기지 않는다.

공유가 닫혀 있으면 서버가 남의 제출물을 아예 주지 않는다. 화면에서 숨기는 게 아니다.

동의 여부와 운영진 권한은 `middleware.ts`에서 한 번에 막는다. 화면마다 검사를 흩어 놓으면
하나 빠뜨렸을 때 그 문으로 다 들어온다. 동의 쿠키는 계정을 만들 때 소비하고 바로 지운다.

장표 PDF는 브라우저에서 Supabase로 바로 올라간다. 서버는 일회용 서명 주소를 발급하고
경로만 받아 기록한다. Vercel의 요청 본문 상한이 4.5MB라 서버를 거치면 4MB짜리 장표가
아슬아슬하기 때문이다. 지금 상한은 20MB다.

PDF 워커는 `public/pdf.worker.min.mjs`에서 서빙한다. CDN을 못 잡아도 장표는 열려야 한다.
`npm install`의 postinstall이 react-pdf가 쓰는 버전으로 복사해 둔다.

## 리허설

9월 12일 전에 `/admin`에서 리허설 회차로 아래를 끝까지 돈다. 브라우저 두 개가 필요하다.

1. 운영진 계정과 참가자 계정으로 각각 로그인한다
2. 리허설 회차에 장표를 올리고 세션을 시작한다
3. 참가자 화면이 장표로 바뀌는지 본다. 장을 넘겨도 운영진 화면은 안 따라간다
4. 2부로 넘긴다. 3초 안에 폼으로 바뀌고 타이머가 뜨는지 본다
5. 참가자가 `/deck`을 직접 열어 본다. 3초 뒤에 안 끌려가는지 본다
6. 칸을 채우다 새로고침하고, 와이파이를 껐다 켠다
7. 제출한다. 콘솔 제출 현황이 차는지 본다
8. 공유를 연다. 참가자 화면에 제출물이 보이는지 본다
9. 세션을 닫는다. 참가자가 `/home`으로 가는지 본다
10. 콘솔에서 리허설을 초기화한다

Auth.js 구글 provider, react-pdf.

만족도, 전사본과 요약, 운영 기록 입력, 회차 간 비교·누적 분석, 사전 과제, 역할 변경과
계정 삭제는 아직 구현하지 않았다. Phase 2 전체를 적용한 상태는 아니다.

## 주제·폼 준비와 종료 확인

`/admin`의 각 회차에서 **주제·폼 편집**으로 들어간다. 주제와 질문 문장을 수정하고 질문을
추가·삭제하거나 위아래로 옮긴 뒤 **폼 저장**을 누른다. 장표와 질문이 하나 이상 있어야 시작할 수 있다.
진행 중·종료된 회차 및 기존 작성·제출 기록이 있는 회차는 폼이 잠긴다. 리허설 초기화는 기존
제출물을 보존하므로 초기화 후에도 작성 기록이 있으면 폼을 수정할 수 없다.
다른 창의 편집이나 세션 시작과 충돌하면 서버가 저장을 거부하고 입력 내용은 화면에 유지한다.
시드를 다시 실행해도 기존 폼의 주제·질문을 덮어쓰지 않는다.

종료 후 운영진은 **회차 결과**에서 기록을 확인한다. 접속·작성 기록이 있는 사람만 집계하고
결석을 추정하지 않는다. 참가자는 `/home`의 **지난 내 제출물 보기** 또는 헤더의 **내 제출물**로
종료된 회차의 제출 답변을 읽는다. 미제출 초안은 이 목록에 포함되지 않는다.
