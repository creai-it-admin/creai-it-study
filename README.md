# CREAI+IT AI 스터디 앱

스터디 운영을 굴리고, 다음 운영을 고칠 데이터를 쌓는다.

참가자는 HTML 장표를 각자 보고 인클래스 답변을 남긴다. 운영진은 한 기기에서
녹음을 시작·일시정지·재개하고, 녹음을 종료하면서 세션을 마친다. 구간별 타이머와
자동 화면 전환은 없다. 녹음·전사본·요약은 로그인한 참가자들이 함께 열람한다.

## 세팅

```bash
npm install
cp .env.example .env      # 값을 채운다
npm run db:deploy         # 저장된 마이그레이션을 적용한다
npm run db:seed           # 최초 설치 시 회차와 1주차 폼을 넣는다
npm run storage:setup     # HTML/녹음용 비공개 버킷을 준비한다
npm run dev
```

### 환경 변수

| 이름 | 무엇 |
| --- | --- |
| `NEXTAUTH_URL` | 로컬은 `http://localhost:3000` |
| `NEXTAUTH_SECRET` | `openssl rand -base64 32`로 만든다 |
| `DATABASE_URL` / `DIRECT_URL` | Supabase Postgres 접속 문자열 |
| `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` | 서버의 장표·녹음 저장소 접근 |
| `SUPABASE_MEDIA_BUCKET` | 비공개 버킷. 기본 `study-media` |
| `OPENAI_API_KEY` | `.env.local`에 설정하는 전사·요약 API 키 |
| `OPENAI_TRANSCRIBE_MODEL` | 기본 `gpt-4o-mini-transcribe` |
| 리포트 모델 | `gpt-5.6-sol`, reasoning `medium` (서버 코드에 고정) |
| `ADMIN_EMAILS` | 운영진 예약 이메일. 공개 가입을 막을 뿐 권한을 자동 부여하지 않는다 |

**퍼블릭 레포다.** `.env`와 `.env.local`은 커밋하지 않는다. 참가자 이메일은 코드에도 시드에도 환경 변수에도
안 들어간다. 각자 이메일과 비밀번호로 가입하면 그때 계정이 생긴다.

### 이메일 / 비밀번호 계정

`/routes/login`에서 이름·이메일·비밀번호(10~128자)와 기록 활용 동의를 받아 가입한다.
이메일은 로그인 식별자이며 소유 여부를 인증하지 않는다. 새 계정은 항상 참가자다.
비밀번호는 무작위 salt를 사용하는 scrypt(N=32768, r=8, p=3) 해시로만 저장한다.
로그인 시도는 이메일별 15분에 10번, 전체 300번으로 제한한다. 가입/비밀번호 설정은
각각 전체 15분에 30번으로 제한하며 카운터는 DB에 저장한다.

운영진 계정은 먼저 일반 계정으로 가입한 후 신뢰할 수 있는 로컬 터미널에서
`npm run auth:admin`으로 권한을 부여한다. `ADMIN_EMAILS`의 예약 주소는 공개 가입이
막히므로 새 운영진을 해당 주소로 가입시키려면 먼저 예약 목록에서 제거한다.

비밀번호를 잊었으면 운영진이 본인을 확인한 뒤 `npm run auth:password-setup`을 실행한다.
출력되는 일회용 링크를 본인에게만 직접 전달한다. 링크는 1시간 후 만료되며 새 링크를
발급하면 이전 링크는 무효가 된다. 비밀번호를 바꾸면 이전 로그인 세션도 무효가 된다.
자동 이메일 발송은 사용하지 않는다.

Google provider와 동의 쿠키는 제거했다. 기존 Google 계정과 스터디 기록은 삭제하거나
자동 변환하지 않는다. 같은 이메일로 재가입하여 기존 계정에 접근할 수 없다.
기존 계정의 비밀번호 설정이 필요할 때만 위 운영진 명령을 명시적으로 사용한다.
기존 Google 로그인 세션은 새 인증에서 인정하지 않는다.

마이그레이션 `202609100001_password_auth`는 비밀번호/세션 버전 열, 이메일 대소문자
중복 방지 인덱스, 로그인 시도 제한 테이블을 추가한다. 대소문자만 다른 중복 이메일이
있는 DB에서는 인덱스 생성이 실패하므로 적용 전에 중복을 확인한다.
`202609100002_auth_table_access`는 User/VerificationToken/AuthRateLimit에 RLS를
켜서 공개 Supabase API에서 인증 데이터를 읽거나 쓰지 못하게 한다. 서버의 Prisma
접속 역할은 이 테이블의 소유자 또는 BYPASSRLS 권한이 있는 신뢰된 역할이어야 한다.

## 스터디와 회차

`Study`가 여러 `StudySession`을 묶는다. 회차 번호는 스터디 안에서만 고유하다.
`/routes/admin`에서는 스터디 목록을 보고, 선택하면 해당 스터디의 1~4주차를 관리한다.
**새 스터디 만들기**에서 이름과 각 주차의 실제 날짜를 입력하면 네 회차가 함께 생성된다.
기존 회차와 리허설은 **0기 스터디**에 소속되며, 리허설은 주차 목록 아래에서 별도로 연다.
기존 회차 ID, 자료, 제출물, 출석, 녹음은 그대로 유지한다.

회원의 스터디 소속은 `StudyMembership`에 저장한다. 일반 회원은 배정된 스터디의 자료·녹음·인클래스만 접근할 수 있고, 운영진은 전체 스터디를 관리한다. 신규 가입은 참가자 권한으로 생성되며 자동 배정하지 않는다. 동시 진행 세션은 앱 전체에서 하나다.

## 어떻게 도나

운영진이 회차의 진행 콘솔에서 **녹음 시작**을 누르면 마이크 권한을 요청하고 세션을 연다.
한 번에 한 세션만 진행한다. 녹음한 브라우저와 계정에서 **일시정지 / 재개 / 녹음 종료 · 세션 마치기**를
사용한다. 종료는 저장된 녹음이 서버에 모두 확인된 뒤에만 완료되고, 종료된 회차를 초기화하지 않는다.
기존 구간 기록과 제출물은 보존되며 새 운영 흐름에서는 구간을 사용하지 않는다.

참가자 화면은 세션 상태만 3초마다 갱신한다. 장표·인클래스·공유 화면은 자유롭게 이동한다.

### 녹음·전사·요약

녹음에는 HTTPS 또는 localhost와 MediaRecorder·IndexedDB·Web Locks를 지원하는 브라우저가 필요하다.
녹음 탭은 열어 두고 기기 절전을 막는다. 다른 자료는 새 탭에서 연다.
음성은 5초마다 브라우저 저장소에 보관하며 약 1분씩 독립 재생 가능한 파일로 서버에 저장한다.
네트워크 오류 시 로컬 녹음을 유지하고 **저장 재시도**로 다시 전송한다. 같은 파일의 중복 전송은
기존 업로드를 확인한다. 새로고침 후 남은 녹음도 같은 브라우저에서 복구한다.
브라우저가 종료되기 직전 아직 저장되지 않은 음성은 손실될 수 있다.

세션 종료 시 서버 워커가 저장된 녹음을 자동으로 전사하고, 전사가 끝나면 GPT 5.6 Sol
(`gpt-5.6-sol`, reasoning `medium`)에 구조화된 리포트를 요청한다. `lib/reports/schema.ts`의
엄격한 JSON Schema와 `prompt.ts`의 시스템 프롬프트를 사용한다. 실제 근거가 없는 영역은
생략하고, 제안과 합의, 계획과 수행을 구분한다. 근거 인용문이 전사본에 실제 존재하는지도 검증한다.
`render.ts`가 JSON을 A 에디토리얼 템플릿에 안전하게 조립하고 비공개 저장소에 HTML을 올린 뒤
해당 회차를 완료 상태로 표시한다. 원본 음성과 전사·리포트 내용은 OpenAI API로 전송된다.

`npm run dev` / `npm start`는 웹 서버와 워커를 함께 실행한다. 브라우저를 닫아도 처리하며,
서버가 재시작되면 저장된 진행 상태를 이어간다. 완료된 전사와 요약은 다시 생성하지 않는다.
업로드 실패 시 저장된 JSON으로 재시도하고, 한 단계에서 3회 실패하면 운영진에게 재시도 버튼을 표시한다.
별도 호스트에서는 `npm run reports:worker`를 상시 실행할 수 있다. Node 런타임과 tsx 설치가 필요하다.
**Vercel 웹 배포만으로 워커가 실행되지는 않는다.** 배포 시 워커를 별도 상시 Node 프로세스로 운영해야 한다.

멤버와 멘토는 해당 스터디에 배정된 계정으로 `/routes/sessions/[id]`에서 같은 리포트를 읽는다.
운영진은 전체 회차를 열람할 수 있다. 리허설은 관리자 전용이다. `/routes/sessions/[id]/report`는
매 요청에 권한을 확인하며 저장소 공개 URL을 제공하지 않는다. 크게 보기에서 브라우저 인쇄로
PDF 저장이 가능하다. 서버 PDF 생성이나 외부 발송은 포함하지 않는다.

### HTML 장표

`.html` 또는 `.htm` 단일 파일을 최대 20MB까지 업로드한다. CSS·JS·이미지는 파일 안에
포함하거나 HTTPS 주소를 사용한다. 상대 경로 파일 묶음은 지원하지 않는다.
업로드는 서명 주소로 비공개 Supabase 버킷에 직접 전송한다. 앱 서버는 경로와 HTML을 검증한다.
장표는 인증된 경로의 sandbox iframe으로 열며 계정 쿠키·앱 DOM 접근과 API 요청을 차단한다.
장표 자체의 스크립트와 화면 전환은 동작한다. 기존 PDF는 원본 경로를 보존하지만 새 뷰어에서는
HTML 재업로드를 안내한다.

인클 폼은 입력 즉시 브라우저에 초안을 남기고, 입력을 멈추고 2초 뒤에 서버에 저장한다.
저장 요청은 하나씩 보내며 10초 안에 응답이 없으면 5초 뒤 재시도한다. 새로고침 후에도
초안과 제출 요청을 복원해 다시 보낸다. 브라우저 저장소를 사용할 수 없으면 화면에 알린다.

저장은 처음 불러온 제출물 ID와 저장 버전을 확인한다. 회차가 닫혔거나 다른 저장과 충돌하면
초안을 보존하고 안내한다. 충돌 안내가 나오면 글을 확인한 뒤 다시 제출한다.

공유가 닫혀 있으면 서버가 남의 제출물을 아예 주지 않는다. 화면에서 숨기는 게 아니다.

동의 여부와 운영진 권한은 `middleware.ts`에서 한 번에 막는다. 화면마다 검사를 흩어 놓으면
하나 빠뜨렸을 때 그 문으로 다 들어온다. 동의는 회원가입 요청에서 확인하여 계정에 저장한다.

## 진행 검증

리허설(0주차)은 관리자 전용이다. 회원 흐름은 별도 테스트 스터디의 일반 회차에서 확인한다.

1. 운영진과 참가자 계정으로 각각 로그인한다.
2. HTML 장표를 업로드하고 버튼·키보드로 넘겨 본다.
3. 진행 콘솔에서 녹음을 시작하고 참가자는 장표와 인클래스를 자유롭게 오간다.
4. 답변을 쓰고 새로고침 후 복원·제출·공유를 확인한다.
5. 녹음을 일시정지했다가 재개한다. 네트워크 오류 후 저장 재시도를 확인한다.
6. 녹음을 종료하고 결과 화면을 닫아도 리포트가 만들어지는지 확인한다. 참가자 계정에서 리포트·녹음·전사본을 확인한다.

## 주제·폼 준비와 종료 확인

`/routes/admin`의 각 회차에서 **주제·폼 편집**으로 들어간다. 주제와 질문 문장을 수정하고 질문을
추가·삭제하거나 위아래로 옮긴 뒤 **폼 저장**을 누른다. 녹음 시작에는 장표·질문 등록을 강제하지 않는다.
진행 중·종료된 회차 및 기존 작성·제출 기록이 있는 회차는 폼이 잠긴다. 기존 작성 기록이 있는 회차의 폼은 수정할 수 없다.
다른 창의 편집이나 세션 시작과 충돌하면 서버가 저장을 거부하고 입력 내용은 화면에 유지한다.
시드를 다시 실행해도 기존 폼의 주제·질문을 덮어쓰지 않는다.

종료 후 운영진은 **회차 결과**에서 기록을 확인한다. 접속·작성 기록이 있는 사람만 집계하고
결석을 추정하지 않는다. 참가자는 `/routes/home`의 **지난 내 제출물 보기** 또는 헤더의 **내 제출물**로
종료된 회차의 제출 답변을 읽는다. 미제출 초안은 이 목록에 포함되지 않는다.
